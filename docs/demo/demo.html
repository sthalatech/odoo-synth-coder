The full-context agent thesis

“What if every issue shipped with
its own prod-realistic, ready-to-run agentic environment??”

Running everything inside a single sandbox means the agent has the same low-latency access to services, files, and tools that an engineer would have locally.
odoo-synth builds that sandbox per issue — a masked, pruned copy of the production database, the addons repo, and Odoo in one isolated workspace — then hands it to an autonomous agent that reads the report, implements the fix, and opens the pull request.

The shift: stop running standups the old way. Curate the issues, file them in GitHub, and assemble later to review the PRs — each one ready in 45–60 minutes, all running in parallel because every agent already has everything it needs in its own self-contained workspace.

The pipeline produces one ready workspace per issue. The agent layer runs them all at once.

One GitHub issue spins up one isolated, self-contained workspace — then one agent goes to work.

What this changes for the team

Curate issues — Review PRs.

A self-contained sandbox per issue means agents don’t queue for an environment, a database, or context. They run in parallel, and a reviewable PR lands in 45–60 minutes. The standup becomes a curation, and the real meeting is the review.

Old standup

  • “What did you do yesterday?”
  • “What are you doing today?”
  • “Any blockers?”
  • Wait for an environment
  • Hand off context, one ticket at a time
  • Fix, then wait for review

New standup

  • Curate the issues worth solving
  • File them in GitHub — the webhook spins up a sandbox per issue
  • Agents explore, fix, and open PRs in parallel
  • Review the PRs/Give feedback to the agents
  • Approve, merge, close — done
